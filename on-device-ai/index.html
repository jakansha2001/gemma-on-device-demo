The round trip

That round trip isn't free.

Latency

The user waits for the network before the first word appears, and longer on a weak connection.

Cost

You pay per token, so the bill grows as more people use the feature.

Privacy

Whatever the user typed, photographed or recorded leaves their phone.

Availability

No signal means no feature, whether that's on a flight or on patchy mobile data.

A few terms before we go further

Five terms you'll hear today.

Parameters

The numbers a model learns in training, also called weights. More usually means more capable, and more memory.

Tokens

The small chunks of text a model reads and writes, often parts of words.

Context

How many tokens the model can keep in mind at once. E2B supports 128K, and the on-device build we use supports up to 32K.

Quantization

Storing the weights with fewer bits. Our model mixes 2-, 4- and 8-bit weights to fit in a 2.6 GB file.

Inference

Running the model to get an answer. In this app, that happens on the phone's GPU.

How the package is put together

A small core, plus what you actually use.

flutter_edge_aithe core, always needed
flutter_edge_ai_litertlm.litertlm engine: mobile, desktop, web
flutter_edge_ai_speechspeech-to-text and text-to-speech
flutter_edge_ai_mediapipe.task engine: mobile, web
flutter_edge_ai_ragon-device RAG
flutter_edge_ai_agentagent skills
flutter_edge_ai_onnxONNX Runtime
Why it is split up

Every engine comes with its own native libraries. Splitting them up means your app only ships the ones it uses.

The catch

The core doesn't register an engine for you. Forget to add one and the app still compiles, then fails at runtime.

Step 3 · Send a message, stream the reply

Stream the reply as it's written.

chat_screen.dart
await chat.addQueryChunk(
  Message.text(text: prompt, isUser: true),
);

await for (final r in chat.generateChatResponseAsync()) {
  switch (r) {
    case TextResponse(:final token):
      answer += token;
    case ThinkingResponse(:final content):
      reasoning += content;
    case FunctionCallResponse():
    case ParallelFunctionCallResponse():
      break;
  }
}
A sealed type

ModelResponse is sealed, so the switch has to handle every case. A new response type gives you a compile error instead of silently lost tokens.

Adding an image is one change

Step 4 · Let the model call your code

Declare a tool, run it when asked.

1 · Declare the tool
final chat = await model.createChat(
  modelType: ModelType.gemma4,
  supportsFunctionCalls: true,
  tools: const [
    Tool(
      name: 'add_task',
      description: 'Add a task to the to-do list.',
      parameters: {
        'type': 'object',
        'properties': {
          'title': {'type': 'string'},
        },
        'required': ['title'],
      },
    ),
  ],
);
2 · Run the loop
await for (final r in
    chat.generateChatResponseWithTools(
  onToolCall: (call) => runTool(call.name, call.args),
)) {
  if (r is TextResponse) answer += r.token;
}
The package runs the loop

It sends each result back to the model until it replies without calling a tool.

Your code runs the tool

Return an {'error': …} map instead of throwing. A throw ends the stream, but the model can recover from an error map.

Building On-Device AI Apps with Flutter & Gemma31 / 43

Lesson 1

Two settings you have to get right.

FlutterEdgeAi.installModel(
  modelType: ModelType.gemma4,       // not ModelType.gemmaIt
  fileType: ModelFileType.litertlm, // defaults to .task if left out
)
model.createChat(
  modelType: ModelType.gemma4,       // defaults to gemmaIt if left out
)
ModelType.gemma4

Tells flutter_edge_ai how to talk to Gemma 4, including its built-in tool calls. It doesn't pick the model; the file does. Leave it out of createChat and it uses gemmaIt, the older Gemma setting, so tools are pasted into the prompt as plain text.

ModelFileType.litertlm

Decides which engine opens the file: LiteRT-LM or MediaPipe. It isn't worked out from the file name, and it defaults to .task, the MediaPipe format. Leave it out and your .litertlm model won't load.

Building On-Device AI Apps with Flutter & Gemma32 / 43

Lesson 2

Images only work in the main session.

openChat()

Opens extra sessions that run side by side on one loaded model. Handy when each screen needs its own conversation.

On the .litertlm engine, though, their history is replayed as text when the engine switches between them, so they reject images.

createChat()

Uses the model's main session, which accepts images and audio.

The exact error I got:
Image/audio input is not supported on concurrent (openSession) .litertlm sessions — their history is replayed text-only on switch.

Text chat worked fine and every image failed. The fix was changing one method name.

Lesson 3

Speech models listen for a fixed length.

My first voice turns were cut off mid-sentence, and nothing in the logs said why. A speech-to-text model is exported with one fixed window. Anything longer than that is dropped, quietly.

Moonshine Tiny
5s

The filename says it: moonshine_tiny_5s_f32.tflite. Say a sentence and a half, and only the first five seconds reach the model.

Whisper Tiny
30s

A 30-second window, and multilingual. That is what makes a real conversational turn possible, so this is what the demo ships.

What I do now

Cap the recorder below the window — mine stops at 25 seconds — and show the countdown while it listens. Short audio is padded, so there is no cost to stopping early.

The same holds for whichever model you pick: read the window it was exported with.

Lesson 4

Small models slip into other languages.

An actual reply from the voice demo

Yes, I know about Flutter. It is an open-ソース software development kit created by Google…

Why

The model knows the same word in many languages. ソース is Japanese for “source”, and with loose sampling it can beat the English word.

What helped
  • Tighter sampling, such as temperature 0.7 for chat and 0.3 for voice
  • Say which language to use in the system instruction
  • For speech, remove characters the voice can't pronounce

That made it rare, but it still happens now and then.
